# Isolated Workers + D1 candidate

This candidate preserves the Node runtime unchanged. It has a native Worker fetch API, a separate guided synthetic-form UI, native WebCrypto receipts and real D1 SQL storage. It is **not approved for deployment**. The local proof passes functional boundaries, but does not establish that every hosted request fits Workers Free's 10ms CPU limit. In the reproducible local inspector run, mocked-model sampled active V8 time had p95 12.663ms and maximum 20.387ms; recovery p95 was 6.193ms and maximum 6.245ms. These are debugger samples, not Cloudflare CPU accounting. The model route exceeds 10ms even in this narrower sample; keep the Node fallback.

## Reproduce locally

Use the cloud checkout, Node >=24.19.0 and the repository lockfile. No laptop setup is needed. The direct Miniflare5.20261012.1-beta pin aligns with Wrangler4.151.1 and avoids the older toolchain advisories; its prerelease API is an explicit development-tool risk. Tests use the official v4-to-v5 migration adapter with an explicit ESM manifest, resourcePersistencePath and a deny-by-default native outbound mock service.

```sh
npm ci
PLAYWRIGHT_BROWSERS_PATH=.cache/ms-playwright node --test test/workers-runtime.test.mjs test/workers-browser.test.mjs
XDG_CONFIG_HOME=/workspace/neb-hackath/.cache/wrangler-config WRANGLER_SEND_METRICS=false npx wrangler deploy --dry-run --config workers/wrangler.jsonc --outdir .cache/workers-dry-run
node scripts/workers-benchmark.mjs .cache/workers-benchmark.json
```

`deploy --dry-run` only bundles locally. The configuration disables workers.dev and previews, contains an intentionally fake D1 ID, and leaves inference inactive. Do not remove `--dry-run` or create resources without separate hosting authorization. `wrangler dev --local --config workers/wrangler.jsonc` requires first applying schema.sql locally and injecting a synthetic local RECEIPT_KEY of at least32characters using a protected local binding. The fully automated tests and benchmark configure fresh local D1 databases and synthetic secrets directly; neither needs a Cloudflare account or real provider key.

## Boundaries

- Cookies are HttpOnly, SameSite=Strict and Secure on HTTPS, with30minute retained server sessions. Every run, diagnosis and approval query binds session/run identity. Writes require same-origin Origin. Request bodies are bounded to20KB. Trace contract remains14KB/40events; form journal is bounded before growth.
- Three real draft/form submission steps validate the supplied synthetic fields. Intermediate progress and misleading success do not commit. A unique run-bound, canonical task/payload SHA-256 digest and HMAC-SHA256 receipt establish completion. WebCrypto verifies the HMAC directly. Workers ports are pinned in ports.json and parity/interop tests require Node behavior equivalence.
- An accepted executable diagnosis must bind the current trace digest and explicit approval. D1 batch consumes a unique approval and CAS-updates the matching run version. Concurrent replay produces one success and one conflict. Since fictional commits are in the same D1 transaction, there is no external write/commit ambiguity. Runtime restart retains receipts, session ownership, consumed approvals and account reservations.
- Native model transport uses only the fixed Nebius HTTPS endpoint, server-only NEBIUS_API_KEY, an exact NVIDIA Nemotron model, ACCESS_CODE header authorization and separately approved SQL campaign. Model/source/catalog digest, integer catalog-derived input/output nanoUSD per token, token cap, maximum POST count and campaign envelope must be pinned before activation. Campaign expiry must be in the next24hours; expiry is checked again inside atomic D1 admission. All inference hard-stops at December15 2026 20:00UTC (December16 01:30India time). The exact existing diagnostic system prompt and supported temperature1/top_p1 sampling are preserved. Conservative input-size envelope plus configured output cap must fit each .02 reservation. A manual redirect policy rejects every non200 status without following it. Provider model, usage arithmetic, finish reason, schema and citations are checked. Model output passes the existing conservative acceptance boundary; it never proves completion or approves a recovery.
- Atomic admission locks the imported account, adds full reservation, appends immutable ledger evidence and advances global/session quotas before POST. Limits:100lifetime,20UTCday,2session and.5total reserved inference envelope. Campaign and lifetime account limits also apply. Successful bounded usage settles conservatively in integer nanoUSD; network/provider/schema/crash failures retain full reservation **and active lock**. No retry, fallback, resume or automatic crash unlock exists. The single account blocks concurrent replicas from spending through the D1 path. Public write quotas additionally cap100new sessions/day,200writes/session/day and1000global writes/day. Reads still consume Workers/D1 limits; this is not a comprehensive abuse defense or availability guarantee.

## Import account history before any inference

`account-history.jsonl` is a non-secret snapshot of the canonical existing account history, not a provider balance statement. It contains the owner-attested59start and50judge reserve plus historical B–L costs, including the full unknown H reservation. Refresh from the canonical retained ledger immediately before a separately approved migration; later Node activity makes a prior snapshot stale.

```sh
node scripts/workers-import-account.mjs workers/account-history.jsonl .cache/workers-account-import.sql
```

The script produces reviewable offline SQL only; it neither connects to Cloudflare nor enables a campaign. Apply schema and import together to a new local database for testing. Immutable import fields, append-only ledger triggers, consumed historical campaign IDs and primary keys reject a second import. An unsettled historical campaign keeps the new account locked. Keep the canonical Node account inactive before any actual migration; independent Node and D1 ledgers cannot protect each other against simultaneous writes. No hosting or model activation is authorized by this candidate.

## Evidence and limits

feasibility-results.json records30samples/operation across two isolated local cohorts: session creation, challenge creation, each form step, incomplete/complete verification, deterministic diagnosis, explicit approval, recovery and a mocked model completion. The benchmark enables an absent-by-default local instrumentation binding that records actual D1 query metadata. It uses workerd's V8 inspector profiler at100µs intervals and excludes idle/program samples. Native crypto, SQLite service and other runtime-thread CPU are not comprehensively measured, while debugger/instrumentation overhead is included. The raw-profile SHA-256 is recorded; compressed full profiles are retained in feasibility-profiles.json.gz; the recorded SHA-256 addresses the uncompressed JSON. Repeating the benchmark rewrites only its requested output files.

Only the seven explicitly implemented scenario IDs are admitted; unsupported renamed, unlabeled and injection variants are rejected rather than silently simulated as clean. The frontend is a small guided candidate, not feature parity with the existing Node workbench: no exports, full trace navigation, campaign administration or public authentication service. Catalog/price snapshots require operator review; this candidate does not automatically fetch or revalidate catalog freshness. Cloudflare account entitlement, route/D1 limits, real hosted request CPU, geography, retention/backup operations, public access controls and sustained availability through the required December16 2026 01:30India-time judge window remain unverified. Any approved hosting plan must retain configuration/secrets/database and operational ownership through that window, avoid a Free-plan upgrade or card, and keep a stable judge-access plan. Static/local success cannot promise availability. No resources were created, no site was deployed and no actual NVIDIA call was made by these candidate tests.
