# Workers Free + D1 hosting assessment

Research basis: source `2066626`, official public pages retrieved October 18, 2026. [Machine-readable evidence](../../results/workers-hosting-research.json) records exact URLs, retrieval times, response/body/text hashes and selected excerpt hashes. These are current public-plan facts, not an account entitlement, hosting test, immutable price guarantee or authorization to publish. Research made HTTPS GETs only; no paid API, model call, provider account/resource creation or deployment occurred.

**Decision: Cloudflare Free feasibility is UNKNOWN; public deployment remains NO-GO until account and hosted acceptance gates pass.** A Worker/D1 implementation replaces the documented Node SQLite/file-lock durability boundary; the current Node/Caddy service cannot simply be uploaded unchanged. Local feasibility, even if independently tested, cannot establish actual Workers CPU consumption, account quotas, durable remote commits or public judge access.

### October20 hotspot optimization and release decision

The original same-suite local model-route profile recorded sampled active V8 p95 **15.003ms**, maximum20.410ms, and p95 D1 reads134 rows. The follow-up made two focused accounting changes: D1 covering indexes on `(campaign_id, kind, nano)` and `(kind, id, nano)`, and duplicate-reservation detection via the deterministic primary key instead of scanning `reservation_id`. A real workerd/D1 test checks both query plans use those indexes; existing tests still exercise ledger immutability, reserve-before-request, settlement, replay denial and crash lockout.

Thirty mocked model-route samples across two cohorts produced p95 sampled-active-V8 **11.661ms**, maximum19.149ms, p95 D1 rows-read67, and p95 rows-written20 (up from16 due to index maintenance). A repeated same-source sample recorded12.432ms active-V8 p95. These runs enable `LOCAL_METRICS` instrumentation and the 100µs inspector sampler; local sample duration is not the Cloudflare platform's billed CPU field and cannot be compared to its10ms Free invocation cap. Therefore this result neither passes nor fails Cloudflare CPU feasibility. It motivated the accounting indexes but is **not** a hosting verdict. Zero NVIDIA requests and zero resources were used. Exact results, source hashes, comparison and compressed raw profiles are in [the initial benchmark](../../results/workers-hotspot-2026-10-20.json) and [repeat](../../results/workers-hotspot-2026-10-20-followup.json).

The current public limits pages were re-read October20: [Workers limits](https://developers.cloudflare.com/workers/platform/limits/) and [D1 pricing](https://developers.cloudflare.com/d1/platform/pricing/). They still publish10ms Workers Free CPU and daily Free D1 quotas of5million rows read and100,000 rows written. The D1 p95 counts above are per local request, not account-wide projections. A real isolated Free account run would be the only valid test of exact per-route CPU, actual quota counters, remote transaction durability and restart recovery; provisioning and public access remain separately gated.

### Documented fallback selection

No alternative is currently verified as a free, card-free, persistent host available to this project through the judge period. Keep the existing Node/Caddy + retained SQLite design as the release reference because its state, receipt, recovery and HTTPS contracts are already tested locally. A Node VM could host it unchanged only after the owner verifies an isolated, unused account and retained volume. **Oracle Always Free is only a conditional investigation, not a resource this session can assume exists; no Oracle account, VM, capacity, payment status or ownership was verified.** Vercel Hobby + Neon would require a database/locking migration; eligibility, pause/reset behavior and both accounts' no-charge entitlements are unverified. Render Free's ephemeral disk and expiring database do not satisfy retention. No unrelated account or project may be borrowed, and no service was provisioned.

## Actual account evidence and blocker

### October 20 release-candidate validation

The optimized indexed D1 candidate has a complete local HTTPS integration run using a self-signed certificate whose SPKI is pinned in Chromium. Real Chromium and persistent local Miniflare D1 completed the synthetic transient-failure recovery only after an explicit approval, validated the signed receipt after disposing and recreating the Worker runtime, and then rejected a misleading-success case as incomplete. The false-success diagnosis abstained and exposed no executable recovery. The mock outbound provider recorded zero requests. This strengthens local restart and browser evidence; it does **not** establish a public HTTPS deployment or real account-level persistence.

The first optimized two-cohort profile measured mock-model sampled active V8 p95 at11.661ms; a repeated profile with the same app sources measured12.432ms. `LOCAL_METRICS` and inspector sampling are enabled in these runs, so neither value is Cloudflare's CPU measurement and they do not establish a 10ms limit failure. The repeat profile and every source hash are recorded in [the follow-up evidence](../../results/workers-hotspot-2026-10-20-followup.json), with its compressed raw profiles. Cloudflare remains unproven until the owner-selected account can run the one-shot [hosted experiment](cloudflare-experiment-runbook.md). The Node service remains the feature reference; no separate durable no-charge host is verified. No Worker/D1 resources or deployments were created.

The callable tool catalog contains no Cloudflare, Vercel or Render provider connector or provider account-status operation. A names/presence-only environment check found no exported variable names containing `CLOUDFLARE`, `WRANGLER`, `VERCEL` or `RENDER`. No credential file or variable value was read. This establishes **no callable provider-account authentication/status capability in this session**; existing CLI login state was not inspected and the owner may have an account. Public documentation GETs cannot inspect billing, identify the account, show remaining shared quota or confirm an account is card-free. Do not request secret values in chat.

Before provisioning, the owner must provide secure scoped account access or review provider dashboard evidence: selected Free plan, no paid subscriptions/add-ons/automatic upgrade, no payment card, quota totals/remaining usage, ability to create one isolated project database, and applicable eligibility. Only then can a no-charge configuration be approved concretely. No billable billing API/upgrade action is needed to assess this.

## Capacity model through December15

Window: October18–December15 inclusive, **59calendar days**, access required through `2026-12-15T20:00:00Z` (noon PST). No assumed free-trial expiry should occur during this period; current public Workers/D1 documentation lists free quotas, not a30day D1 expiry. This is not a guarantee that provider terms or account access cannot change.

The following is an admission-sizing hypothesis, **not measured usage or a judge forecast**:

| Assumed daily workload | Calculation | Free envelope |
|---|---|---|
| 100 synthetic sessions; 100 dynamic requests/session; health once/minute | 11,440 requests/day | 11.44% of100k; count any Worker-routed static assets additionally |
| 5,000 scanned/read rows per session, health without database | 500,000 rows/day | 10% of5m |
| 250 written rows/session including indexes; 5,000/day cleanup/admin allowance | 30,000 rows/day | 30% of100k |
| 20KB retained sanitized evidence/session, including its indexes | 118MB across59days;50MB reserve →168MB | Below500MB database limit; actual `size_after` must confirm |

Keep thirty-minute expiry for private synthetic sessions; do not retain raw traces/contact data indefinitely. Retained receipt/approval/budget evidence must still prevent replay and preserve cumulative spent-credit history. Deletion itself consumes write quota. If evidence averages100KB/session,59days yields590MB before overhead and **fails** a single Free database. At1,000sessions/day, assumed writes alone become255,000/day and fail despite read/request allowances. Growing full-table scans and serialized snapshots invalidate this model. Measure before setting advertised admission limits.

Start with a reviewed daily admission ceiling no higher than100sessions and much lower live inference limits from a separately approved campaign. Warn at50% provider quotas/storage, close new admissions at70%, reserve remaining headroom for completion/verification, cleanup and operator checks. These are proposed application thresholds, not Cloudflare features or independently verified caps. Account-shared usage must be included. Bots can exhaust the public100k quota before code runs; application rate limiting cannot guarantee availability. Avoid public polling loops; one/minute health is the modeled allowance.

Nebius credit reservation is a separate contract: Worker Free does not cap provider inference spend. Preserve the imported cumulative account history, reserve atomically **before POST**, settle actual usage once, keep unknown usage reserved, enforce campaign maximum POST/output/reservation/source/model/price scope, and stop on any failure/expiry. Do not reset daily quotas into fresh model-credit budgets or renew campaigns automatically. Current short campaign windows cannot by themselves authorize NVIDIA operation throughDecember15.

## Concrete configuration and acceptance gates

1. **Before provisioning:** owner authorization for one isolated Free Worker/D1 resource and public deployment; securely verified account/card/plan/quota evidence above. Use a provider-supplied HTTPS `workers.dev` address initially to avoid domain purchases; verify availability/eligibility rather than promising a URL. Keep all other projects untouched.
2. **Reviewable configuration:** a single Worker and one project-only D1 binding, explicit compatibility date, server-only protected Nebius binding scoped to `api.tokenfactory.nebius.com`, no secret build args/assets/logging, bounded input/output sizes, fixed same-origin route URLs, canonical HTTPS origin and Secure/HttpOnly/SameSite cookies. Keep inference disabled until separately approved. No paid Workers, Containers, R2, browser product, email, external marketplace storage or other add-on is implied. Any paid plan or extra resource is a stop condition, not fallback.
3. **Correctness gate:** hosted tests of two concurrent approvals, duplicate/foreign sessions, signed private receipt, CAS conflict/zero affected rows, SQL transaction rollback, over-limit/deleted/corrupt records, unknown provider response and Worker termination before/after reserve/POST/settle. No public success after failed persistence. Distributed Worker instances cannot reuse the Node process/file lock as their authority.
4. **Budget/durability gate:** import and reconcile actual retained budget history; prove accepted consumption/receipt survives replacement Worker version and new instance; test D1 binding absence/failure and simulated quota denial without deliberately exhausting shared provider quota. Unknown outcome remains reserved and manual recovery is required. A SQL transaction cannot span a Nebius HTTP request: durable intent/idempotency and fail-closed reconciliation are required.
5. **Performance/capacity gate:** capture actual hosted CPU per representative route, with p95 comfortably below10ms and no resource-limit errors; bound maximum export/trace/response memory, measure D1 row/index/storage counts including cleanup and migration, and set admission thresholds from evidence. Local Node wall-clock timings do not measure billed Worker CPU.
6. **Public access gate:** actual HTTPS browser journey from outside the provider, session isolation, canonical host/Origin rejection, no spoofed forwarded-header trust, complete synthetic form/recovery/export, genuine NVIDIA result under approved credits, failure/limit messages, deployment replacement persistence and shared quota monitoring. Preserve public URL/build hashes and actual test timestamps; no local fixture may be presented as hosted evidence.
7. **Continuity gate:** owner-supported monitoring and operating schedule throughDecember15, halt/resume rules for quota/plan changes, protected backup/export destination approved separately, recovery practice without resetting credit/approval history, and fresh official-plan checks before publication/submission. Free quotas do not guarantee uninterrupted uptime. Hosted smoke evidence must be refreshed after runtime changes.

If CPU, D1 transaction guarantees, capacity or account no-charge entitlement cannot pass, stop this candidate and assess the alternatives below. Passing local tests alone does not satisfy these gates.
