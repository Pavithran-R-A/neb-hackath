## Historical single-host SQLite/Caddy candidate (not the selected hosted route)

`node scripts/workbench-public.mjs` is a separately selected mode. It fails startup without an exact `https://` `RECEIPTLAB_CANONICAL_ORIGIN` and absolute `RECEIPTLAB_STATE_DIRECTORY`. It still listens only on loopback. `deployment/receiptlab.service`, `runtime.env.example` and `Caddyfile` form a concrete single-host deployment candidate: a nonroot Node service, one local durable volume, and a same-host HTTPS terminator. They have **not** been installed, started publicly, or validated on a hosting provider. There is no account entitlement or no-charge claim. No public DNS, certificates, service, storage, database or paid resource was created.

The gateway must preserve the configured canonical Host and browser Origin, strip `Forwarded` and `X-Forwarded-Host/Proto`, and make the Node listener inaccessible except through that gateway. The runtime rejects those proxy headers, an unexpected Host, and mismatched Origin. It never learns origin or cookie security from a request. HTTPS is the operator's explicit configuration contract; the gateway is trusted to terminate TLS. Public sessions use `HttpOnly; Secure; SameSite=Strict`, retain the existing thirty-minute expiry, and bind every form/API record to its session. All displayed form links use the same HTTPS origin under `/forms/form/{id}`. Browser assets and state updates use `/forms/...`; application evaluator records and signing key remain on the private loopback service. No general URL proxy exists.

`src/runtime/durable-state.mjs` uses Node's built-in SQLite with synchronous `EXTRA` commits and atomic snapshots containing sessions, admission/rate history, diagnoses, consumed approvals, private app records, journal and receipt signing key. A separate SQLite database holds an exclusive OS file lock for the process lifetime. Another instance fails before serving requests; a process crash releases the lock. A crash test actually uses `SIGKILL` and restarts a new HTTP process on the same volume, preserving a committed receipt and session. Database corruption fails startup. A failed write poisons the store so subsequent reads/writes fail closed instead of presenting an uncommitted success. In-flight diagnosis/recovery is quarantined after restart; consumed approvals remain consumed. Expiry still deletes the synthetic session/run. This is single-instance local-filesystem durability, **not** a distributed database, shared-network-filesystem lock guarantee, backup, protection against volume loss, or independently enforceable provider billing cap.

The public script has model inference disabled, even if a key is present. A reviewed model runner can pass `diagnosticPolicy`, `diagnosticBudgetDirectory` and the policy's matching `durableBudgetDirectory` marker to `createWorkbench`; the budget path must be under the persistent state root. The marker is a trusted operator wiring contract, not proof an arbitrary injected policy uses durable accounting. The real runner must reserve cumulative account and campaign ledgers there before any provider POST and preserve unresolved reservations. Never erase, replace or mount an empty budget volume to re-enable a depleted campaign. Node state and budget ledgers must live on the same retained deployment volume. The process lock deliberately prohibits horizontally scaled replicas.
