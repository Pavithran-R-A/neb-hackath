# Bounded action-evaluation campaign (standing authorization, not run in this checkpoint)

`npm run campaign:plan` is local, no network/inference, and prints a source/suite-bound proposal. The owner's standing bounded-inference authorization is recorded in [PR #2 comment #6235724302](https://github.com/Pavithran-R-A/neb-hackath/pull/2#issuecomment-6235724302); the CLI still requires a fresh, source/suite/model/price-bound authorization file derived from that authorization and fresh credit evidence. Writing `approved:true` without the recorded authorization is not permission. The legacy `benchmark --live` path is disabled.

The owner-approved file must include: unique filesystem-safe `id`; `approved:true`; `approvedAt` within 15 minutes; `expiresAt` within one hour of approval; exact clean `sourceCommit`; frozen `suiteSha256` from the plan; exact protected `model`; selected v2 `scenarioIds`; `repetitions` 1–2; `maxRequests` 2–100, including the initial preflight; `maxOutputTokens` 1–1,024; `spendLimitUsd` positive and <=0.50; positive verified input/output USD rates per million; and fresh `creditEvidence` using the existing credit gate. Keep raw financial attestations outside Git.

Before any inference the CLI exclusively creates `.cache/campaigns/<id>.jsonl` (0600). Existing ledgers are refused, including failed/closed/interrupted campaigns. It refreshes account catalog prices and stops on mismatch. The first inference is the strict single-request preflight; any failure ends the campaign. Only after success does the same ledger cover the agent trials and a competent DOM baseline. No scripted substitution, provider retries, model/schema fallback or automatic campaign resume is allowed. Every request reserves conservative allowance, appends and fsyncs **before** the POST. Reservations are not refunded, including HTTP/transport errors or missing usage. Concurrent calls, exhausted calls/credits, expired approval, excessive usage, and unsafe destinations are rejected. Provider/action contract failures stop subsequent trial requests.

Reservation formula: UTF-8 bytes of serialized messages + schema/format + 1,024 framing tokens, multiplied by approved input rate, plus requested output limit × output rate. Requests whose estimated input allowance exceeds 20,000 are denied. Tokenization is estimated; this is **not an account-enforced dollar cap**. Actual overrun cannot be reversed. Account quotas/prices/credits and no-card conditions need owner confirmation; no payment/top-up path exists.

A nine-case, one-repetition v2 campaign has at most 73 calls (1 preflight + 9×8). At the presently cataloged $0.06/M input and $0.24/M output, pessimistically reserving 20,000 input +1,024 output on all 73 gives **$0.10554048**. This is an estimate, not a provider-enforced cap. The PR standing authorization permits bounded work within the recorded budget and judging reserve, but does not justify running a broad benchmark without a product decision. No new campaign described here was executed in this release checkpoint; preserve the actual historical L and partial negative v3 outcomes separately.

Crash/restart: fsynced ledger preserves reservations when the filesystem survives; the same authorization ID cannot be reopened. An interrupted campaign requires investigation and NEW approval, not ledger deletion. Ephemeral hosting or a fresh checkout can lose files; this cannot be a global/account spending control or a public multi-replica budget. Durable shared coordination is a public-demo blocker. The CLI keeps ledger/trial evidence in ignored `.cache`, never raw key, provider text or reasoning. Trial action histories contain synthetic task values and are not a public user-data collection mechanism.
